# 第一周工程复盘：模拟电池数据不一致

核验日期：2026-10-11。本文记录代码事实、历史提交和离线验证，不代表真实电池诊断效果或维修师确认结论。

## 1. 现象与证据

模拟器输出三个电芯电压和总电压，但旧实现的总电压并非来自当次电芯数据。同一条记录因此可能自相矛盾，影响下游诊断输入的可信度。

修复提交为 [`2c3dd63`](https://github.com/lanqi55/ebike-ai/commit/2c3dd63118d9cb72983a560c715b2ed1277efe61)。可在仓库根目录查看修改前后的代码：

```powershell
git show '2c3dd63^:sim_hardware.py'
git show 2c3dd63 -- src/ebike_ai/sim_hardware.py test_cases/test_sim_hardware.py
```

Day 7 从历史源码提取电池字典表达式，将其中的时间调用固定到指定时间戳，再与当前纯函数比较，得到：

| 固定时间戳 | 旧实现总电压 | 当次电芯之和（两位小数） | 当前实现总电压 |
|---|---:|---:|---:|
| 0 | 8.62 | 8.51 | 8.51 |
| 1.23 | 8.62 | 8.64 | 8.64 |
| 123.45 | 8.62 | 9.09 | 9.09 |
| 1000000.0 | 8.62 | 8.51 | 8.51 |

这是本次对历史表达式的离线重放：未启动无限循环、未写硬件日志。它不是当年实际采集的数据，也不是修复前已经执行过 pytest 的证明。原始发现过程没有完整留存，不能宣称当时遵循了“先红后绿”的测试顺序。

## 2. 根因与修复

旧实现让 `cell1`、`cell2` 随时间变化，却始终通过 `round(3.26 + 3.25 + 2.11, 2)` 计算总电压，因此总电压固定为 8.62。多个字段使用了不一致的数据来源。

当前 [`build_battery_data(timestamp)`](../src/ebike_ai/sim_hardware.py) 接收同一个时间戳，先计算各电芯值，再计算 `round(cell1 + cell2 + cell3, 2)`。循环只负责取得时间、调用函数和输出日志。

这样拆分后，传入相同时间戳就得到相同结果；测试不需要等待真实时间变化，也不需要启动循环或写文件。现有数据契约按两位小数比较总电压与电芯之和，避免直接比较未舍入的浮点求和结果；这是一项软件数据约定，不是硬件测量误差标准。

## 3. 如何防止回归

[`test_sim_hardware.py`](../test_cases/test_sim_hardware.py) 使用上述四个固定时间戳，断言总电压等于当次电芯之和保留两位小数的结果。历史重放中的四个输入均能暴露旧实现问题，当前实现均满足一致性要求。

后续提交 [`af1eaf0`](https://github.com/lanqi55/ebike-ai/commit/af1eaf0b9e613e61230010d2793767a36db1e090) 增加了数据契约与入口校验：

- [`battery_data.py`](../src/ebike_ai/battery_data.py)：检查对象结构、必填字段、数字类型、有限值、非负值及总电压一致性；排除布尔值，保留额外元数据。
- [`hardware_collect.py`](../src/ebike_ai/hardware_collect.py)：串口数据写入前校验，不合法的数据不追加到日志。
- [`read_hardware.py`](../src/ebike_ai/read_hardware.py)：读取最后一条日志后再次校验，防止旧日志或其他写入来源绕过采集入口；返回明确的错误信息。
- [`test_battery_data.py`](../test_cases/test_battery_data.py)：覆盖正常值、零值、缺字段、错误类型、非有限值、负值、总电压不一致、舍入，以及无效数据不写入、日志缺失或损坏等行为。

这组测试验证数据生成和边界处理；不证明真实串口接线、传感器精度或电池健康状态。

## 5. 面试表达草稿

以下内容用于组织表达，需要结合代码自行复述，不能把读过草稿视为已经掌握：

> 我在电动车 AI 诊断项目中处理过一个模拟测量数据不一致的问题。模拟器的两个电芯电压随时间变化，但总电压一直由三个固定值计算，因此同一条记录的分电压和总电压会矛盾。比如固定时间戳为 0 时，三个电芯之和是 8.51，而旧代码仍输出 8.62。
>
> 修复时，我把计算提取为接收时间戳的纯函数，用同一次生成的电芯值计算总电压；取时间和写日志保留在外层循环。这样测试可以传固定时间戳，不依赖真实时间，也不用启动无限循环。
>
> 为防止回归，项目使用四组固定时间戳检查总电压与电芯求和的一致性，并按两位小数处理。后续又增加数据契约，在串口写入前和日志读取后校验缺字段、错误类型、非有限值和总电压不一致，避免无效数据进入诊断链路。
>
> 本次完整离线回归有 64 条通过，两条真实模型测试跳过。我也重放了历史表达式，确认这四组输入能够暴露旧问题。不过没有保留下当时先运行失败测试的证据，所以不会声称这是完整的测试驱动开发过程。这些测试证明的是数据一致性和错误处理，不能证明电池安全或 AI 诊断准确率。

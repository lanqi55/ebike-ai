## 运行与查看结果

使用项目已有 `venv`；如安装在 `.venv`，相应替换路径。命令不启用真实模型或 MySQL。

```powershell
Remove-Item Env:DASHSCOPE_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:PYTEST_ADDOPTS -ErrorAction SilentlyContinue
$env:PYTHONIOENCODING = 'utf-8'
.\venv\Scripts\python.exe -m pytest test_cases/test_voltage_rules.py test_cases/test_knowledge_provenance.py test_cases/test_evidence_contract.py test_cases/test_week5_regression.py -q
.\venv\Scripts\python.exe -m scripts.week5_evidence_demo
.\venv\Scripts\python.exe -m pytest -q -rs --tb=short --junitxml=reports/week5/junit.xml
.\venv\Scripts\python.exe -m pip check
```

演示为三个真实案例分别构造合法引用、空检索、旧库缺来源、虚构引用，共 12 个离线场景。`reports/week5/evidence-demo.json` 保留每行实际回答、来源、预期/实际状态和失败列表。异常未捕获时进程非零退出；报告中存在不符合预期的场景也非零退出。生成报告与向量库均不提交。

演示使用真实 Agent、固定假模型和固定假检索。每轮排除被测案例全文，也不加载可能含有衍生答案的任意参考文档；模型输入只从 `diagnosis_input()` 导出，不包含最终判断、维修及复检。其他案例的片段只用于验证传递和引用契约，不宣称是相关检索命中或正确诊断。

## 行为及兼容性

- 硬件输出新增 `rule_result`；现阶段缺少可信车辆关联和人工确认阈值时停止故障推断，列出所需上下文。确定性规则配置冲突也不静默择一。
- 知识工具仍使用 `ok/data/error`，但成功 `data` 是来源片段列表。`retrieved_docs` 聚合本次运行实际返回的片段；同文档不同版本或同片段异文时提示复检。
- 注册了知识工具的诊断 Agent 不能用“直接输出最终答案”绕过来源检查；引用统一写成 `[来源:chunk_id]`。没有来源、没有确认、没有引用或引用未知片段时，丢弃该模型结论，返回固定补充证据提示。
- API 的五个成功顶层字段及字符串类型不变；证据不足仍返回 HTTP 200 的保守回答，不增加会话 ID，也不新增数据库审核接口。
- 新增 `EvidenceJudge` 的“证据引用有效率”；证据不足计入 `insufficient_evidence_count`，该项为不适用，不冒充引用通过。异常仍计入 `failure_count`。CLI 评测脚本原有修改保持不动；返回行新增字段会进入其 DataFrame 报告。
- 只将包含本次已确认引用的正常完成回答放入短期成功记忆；不自动写入长期案例库。

## 验证边界与后续事项

离线测试证明规则计算、来源传递、引用归属、版本冲突处理及接口兼容性。**引用有效不等于语义有依据**：模型仍可能引用真实片段却错误理解内容，或把不相干案例类比到当前车辆。相似检索也不保证适用性；当前检查结果不足时仍需要维修师确认。本周不宣称消除了所有幻觉。

当前没有真实业务电压阈值，合成阈值仅用于代码边界测试；三条案例均不包含电压记录。旧 Word/PDF 没有人工确认记录，默认不可用作已确认诊断引用。真实模型、Embedding、真实检索质量、维修准确率和人工审核入库尚未验证或实现。旧 32 条评测数据及两条关键词 live 测试是历史实验资产，其标签不等于经维修师校验的规则，不能直接作为第五周真实质量结论。

测试环境备注：本轮沙箱内出现 Windows 事件循环 `socketpair` 阻塞、导入子进程超时和临时文件原子替换被拒绝；同一离线测试在沙箱外完成。没有通过跳过 API 测试或删除原子替换来掩盖问题。

三道核心复述题：

1. 为什么数据合法或规则通过，不代表电池正常、安全？
2. 为什么相似案例与有效引用，仍不能直接确认当前故障？
3. 假 LLM、假 Embedding 与真实模型评测分别能证明什么？

下一小步是按 Day 29 开始学习走查；后续取得可靠的规则资料和适用条件后，再开启真实阈值及显式联网质量评测。
